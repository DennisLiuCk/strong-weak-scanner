研究中心 UI UX 審查與改版方案

閱讀器能顯示文章，但入口、版面切換與大量導讀內容，讓使用者難以快速讀到正文並保持方向感。

建議以「文章清單＋站內閱讀」作為預設體驗。主閱讀區先呈現文章，輔助工具由讀者自行開啟；保留證據狀態與來源，移除重複的介面說明。

主要問題

使用者描述的「跳頁」有兩個不同來源。一般文章卡片在同一個 research.html 內開啟，首次使用時預設切成專注模式，隱藏清單與主導覽；來源和 GitHub 原始文件則確實設定為另開分頁。不能將兩種情況混為一談。

實測從儀表板進研究中心、選文，再按瀏覽器上一頁，會直接回到儀表板。手機上的站內「返回研究清單」則正常可用，所以問題是返回方式與模式不一致，不能宣稱所有路徑都無法返回。

優先級問題與影響證據改版決策
P1點文章後，清單和主要導覽消失。版面從文庫變成獨立閱讀畫面，使用者失去原來的搜尋與選文位置；「文章清單」實際是版面模式切換。步驟 2、3；applyFocusMode() 預設啟用。預設保留文庫與研究中心導覽。專注閱讀改為明確的自選模式；返回目的地保持固定。
P1瀏覽器上一頁跳過清單。選文章替換目前歷史項目，無法照「清單 → 文章」的順序回去。步驟 4；setArticleHash() 使用 history.replaceState。文章導航建立歷史項目，支援上一頁／下一頁與深連結；保存篩選、選取列及捲動位置。
P1輔助內容成為閱讀的必經路徑。標題與查核狀態之後，接連出現閱讀任務、結論邊界、新手摘要、角色、學習路線、後續問題與研究摘要，正文被推到下方。步驟 2、5、6；renderReader() 的附加順序。標題、精簡 metadata 後直接呈現主正文。導讀與術語改成可選工具；重要限制保留在相關論述旁。
P1同時顯示篩選、文章清單、正文、大綱，壓縮閱讀欄。使用者在「看得到清單但正文擁擠」與「正文較寬但導覽消失」之間選擇。步驟 3 桌面分欄畫面。常駐兩欄：精簡文章清單＋舒適閱讀欄。篩選、大綱與查核資料以抽屜或浮層開啟。
P2文章入口被大型新手路線遮住。清單與中央空白閱讀區同時介紹如何開始學習；進文庫後仍要先找文章在哪裡。步驟 1。首頁直接提供搜尋與文章清單。新手路線移至「產業探索」；入口只保留一個低調連結。
P2同一觀念反覆包成不同卡片。範例中的「一條會切斷整櫃水電的指令」在閱讀任務、結論邊界與三句重點重複出現。各卡片同時強調「先讀」，缺少真正的主次。步驟 2 的畫面與 DOM 內容。每項內容只保留一個主要位置。不再疊加另一個「先看重點」卡片；以字級、段距與章節結構建立層次。
P2功能名稱偏向內部研究架構。「族群矩陣」首屏主要是學習路線；雷達與圖譜也各自重複教學、任務與證據警語。讀者先理解工具分類，才能讀文章。步驟 8、9、10。上層以「文章」「產業探索」區分工作；「研究追蹤」降為次要入口。保留原工具但收斂各自首屏。
P2跨文章與外部來源的行為不夠清楚。閱讀器上的類型分頁會切換相關文章；正文連結及來源統一另開分頁，與文庫卡片的站內選文方式不同。閱讀器分頁、來源 DOM 與 readerTabs()、readerRunNode()。改成帶文章標題的「相關閱讀」連結。站內研究統一站內打開，外部來源明示「↗ 外部來源／新分頁」。
P2小字與冗長控制名稱增加辨識負擔。清單按鈕的可存取名稱含整張卡片文案，畫面內又充滿小字、巢狀卡片與淡色說明。步驟 1、3、8、10 的截圖與 DOM。文章以簡短標題連結作為主操作，metadata 不塞入按鈕名稱；提高基礎字級並減少非必要說明。

P1＝直接妨礙選文、閱讀或返回；P2＝持續增加理解與操作負擔。優先級是本次設計判斷，並非使用者研究量化評分。

實測流程與截圖

以下均為本次正式網站擷取。點開各步驟可查看完整證據。截圖中的研究內容只用於檢查介面，不在本報告重新驗證其投資或技術主張。

1　進入研究文章　｜　需要改善

文章清單上方放了完整新手路線，中央閱讀區再次要求先選系統問題。搜尋與分類本身可用，但主要的選文工作被教學入口延後。

2　點開市場議題　｜　主要問題

卡片在同頁開啟；預設專注閱讀隱藏清單及主導覽。首屏呈現閱讀任務與結論邊界，尚未出現主正文。右上方「文章清單」可以恢復分欄，但按鈕名稱沒有交代這是模式切換。

3　按文章清單恢復分欄　｜　需要改善

同一篇文章仍在閱讀器內，但篩選、清單、正文與大綱同時佔用橫向空間。恢復清單並沒有消除正文前的輔助內容。

4　用瀏覽器上一頁返回　｜　主要問題

重現順序：儀表板 → 研究中心 → 搜尋 → 開文章 → 瀏覽器上一頁。結果回到儀表板，並未回到研究清單。這是實測行為，與程式使用 replaceState 的結果一致。

5　手機開文章　｜　需要改善

手機已有可見的「返回研究清單」，這項設計值得保留。但閱讀任務仍佔據首屏，「開始讀三句重點」比「直接讀第一節」更突出，正文需要額外找尋。

6　直接讀第一節　｜　功能可用，路徑需縮短

按鈕能捲到正文，證明文章並未缺失。正文前仍插入問題定位與名詞區；手機頂端同時存在網站標頭、返回列與閱讀位置列。

7　手機返回研究清單　｜　可用

站內返回鍵可回到已選文章附近，並顯示選取狀態。這是應保留的優點；本次路徑不代表重整、外部深連結或所有來源路徑都已測過。

8　研究雷達首屏　｜　需要改善

清楚區分待驗證問題與已有文章是優點，但候選題地圖、全部候選、單題卡片及讀法說明重複包裹相同問題。應以簡潔追蹤清單呈現問題、狀態與下一個事件。

9　族群矩陣首屏　｜　需要改善

頁面主要入口是學習路線，與「矩陣」的名稱不相符。每條路線又帶第一站導讀、角色按鈕和預覽，單個選擇負擔偏大。可將路線作為產業探索中的自選入口。

10　知識圖譜首屏　｜　需要改善

圖譜有證據層級、到期狀態及可回查關係，應保留。但新手讀圖、目前選圖、目前讀圖任務與各項警語把圖推到下方。改為先顯示圖與核心圖例，選中關係後再顯示證據。

新方案的共同結構

搜尋或瀏覽文章 → 點選後直接讀正文 → 遇到問題才查名詞或證據 → 返回原清單或接讀相關文章

層級預設呈現需要時才開啟
整個研究中心文章；產業探索；返回掃描儀表板研究追蹤（現有雷達）；工具內的研究覆蓋盤點
文章清單搜尋、精簡類型切換；標題、簡短摘要、日期與必要狀態族群、時間、查核狀態篩選；保留目前條件提示
文章閱讀文章標題、日期、簡短證據狀態、主正文、段落旁引用目錄、閱讀輔助、查核資料；專注閱讀
閱讀輔助一個低干擾入口三句摘要、名詞、角色與學習路線；同一內容不重複呈現
產業探索以族群或問題找內容學習路線、關係圖、研究覆蓋；從文章進來時保留返回該篇的位置

證據邊界仍然必須可見。文章的「推論」「證據待複核」等關鍵狀態保留在標題旁，會改變結論的限制保留在相應正文。收合的是重複導讀、完整查核記錄與操作解說，不是隱藏對研究主張的限定。

三個視覺方向

三個方向共用上述內容規則，差別在選文與閱讀如何共存。以下編號依本次對話中概念圖的實際出現順序。圖中的文章段落與日期為排版示意，實作須回接現有原文，不得拿示意文字覆蓋研究內容。

方向互動方式適用與取捨
文庫雙欄（建議）左側精簡清單，中央／右側主閱讀；點文不改變整體結構。篩選與大綱按需開啟。最符合「留在研究中心閱讀」的需求，便於連續換文。窄螢幕改成單欄與固定返回清單。
閱讀優先使用清楚的文章詳情路由，保留全站導覽、麵包屑及明確返回文章清單；正文居中，清單透過入口召回。長文最舒適；切換文章多一道動作。必須修好瀏覽歷史與清單還原，不能重現目前無預警隱藏導覽的模式。
快速預覽文庫文庫列表作為主畫面；選文打開寬閱讀側板，背景保留原清單，關閉即回原位置。適合大量瀏覽與快速判斷。長文需要「展開閱讀」選項，側板的焦點、捲動與手機行為更需仔細驗證。

文章內容的去留

  • 「這篇先弄懂」：移除框架性 kicker；以文章題名為唯一主要標題，問題式副標只有真正補充意義時才保留。
  • 「新手閱讀任務」「新手先讀」：整合到閱讀輔助，不在每次開文時強制展開。
  • 「先看結論邊界」「完整研究摘要」：去除重複卡片，完整摘要作為可選導讀；關鍵限制就地保留。
  • 「角色定位」「學習路線」「想一想」：搬到閱讀輔助或文末延伸，避免阻擋原文。
  • 「章節接力」「新手讀表」「標題逐字沿用原文」等系統解說：預設移除，用正文標題、表頭與正常排版完成同一工作。
  • 名詞：以就地開啟、可關閉的解釋呈現；完整字典保留入口。
  • 來源：就地引用開啟查核面板，原始文件連結清楚標示外開。

互動契約

  • 站內文章使用正常連結語意，支援複製網址、鍵盤開啟及使用者自行開新分頁。網站自行處理站內閱讀時仍保留可用的深連結。
  • 清單 → 文章 A → 文章 B 的導航建立對應歷史項目；瀏覽器上一頁回 A，再回清單，下一頁也可還原。搜尋輸入可替換同一狀態，避免每個字造成歷史項目。
  • 點選文章保留搜尋、篩選、排序、清單捲動與選取列。返回以目前來源為準；直接開文章深連結則有「所有文章」保底入口。
  • 手機頂端只保留必要的研究中心身份與「返回文章」；目錄以單一按鈕開啟，避免多層固定列壓住正文。
  • 來源、名詞與篩選面板可用 Escape 關閉，關閉後焦點回觸發按鈕；文章切換後焦點到標題，回清單時回原列。
  • 載入、無結果及錯誤要明確顯示，不能以空白閱讀區代替。研究內容可信度與資料載入失敗須分開呈現。

實作順序與驗收條件

先完成文庫與閱讀器的整體替換，再整理探索工具。避免保留所有舊卡片，只在外面多包一層新版外殼。

  1. 導覽與歷史。統一文章路由與返回規則，保留既有 hash 深連結相容性。補上瀏覽器層的前進、後退與清單狀態驗證。
  2. 閱讀主體。重排 scripts/research_template.html；縮減常駐欄位與正文前輔助內容，保留原文章與證據契約。
  3. 探索工具。整合雷達、矩陣與圖譜的上層導覽；在各工具內保留必要的資料與可回查證據。
  4. 使用者走查。用找指定公司文章、讀最新一節、查引用、返回原結果、換下一篇的任務檢查。先收集實測再宣稱閱讀速度或成功率改善。
  • 桌面開文後第一屏可見文章標題與第一段主正文；手機在標題與必要狀態之後立即進入正文，不要求先看導讀。
  • 預設桌面狀態保留研究中心主要導覽與選文入口；專注模式只能由使用者主動開啟。
  • 研究中心清單、文章、相關文章之間的上一頁／下一頁可逆；重整與分享深連結可直接定位文章。
  • 正文、查核狀態、來源、證據期限與個股對應沿用原始資料；不能因精簡介面而改寫成更強的研究結論。
  • 以桌面 1440 × 1000、筆電寬度、手機 390 × 844、放大文字與鍵盤流程驗證；正常閱讀不出現整頁水平溢出，必要寬表格獨立捲動。
  • 以正式筆記、多空小作文、市場議題／事件、無結果、過期證據、長標題與長表格作代表樣本。
  • 既有測試中固定舊導讀標籤或結構的斷言應改為新的行為契約；研究內容與證據完整性測試必須保留。

範圍與限制

本輪使用 Windows、Codex 內建瀏覽器，在正式網站 研究中心 操作。桌面與手機為 CSS viewport 模擬；主要完整閱讀樣本是「AI 機櫃如何判斷控制指令可信」市場議題，其餘工具審查首屏與入口。程式對照來自 git pull 後的本機 1c82e03，未核實正式部署 commit 與其完全一致。

已確認的優點包括：全文可以站內呈現、搜尋可找到目標、跳到第一節有效、手機站內返回能定位原文章、證據狀態與來源有保留。改版應延續這些能力。

可及性方面，本次只查看可見畫面、DOM 標籤及焦點結果。小字、多層捲動、冗長按鈕名稱與固定列構成風險；未完整測試螢幕閱讀器、所有鍵盤流程、深色模式或色彩對比，不宣稱符合完整 WCAG 要求。

初次導覽曾超時，稍後完成載入；沒有做網路與效能基準測試，因此不將這次暫時空白直接定性為產品故障。本文沒有使用者樣本的速度、完成率或滿意度統計，也不估算改善百分比。
