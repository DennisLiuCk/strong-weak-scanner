## 新手先讀：這篇在講什麼

### 名詞小字典

- **Section 301**：美國可針對被認定不公平的外國政策或做法採取關稅等措施的貿易法工具，不是所有商品自動套用同一稅率。
- **HTS code**：美國進口報關使用的商品分類號碼；產品俗稱相同，也可能因規格、組態或用途而落在不同 code。
- **MFN 稅率**：美國對一般貿易夥伴適用的基礎關稅；本題的 Section 301 稅要和它一起判讀。
- **Incoterms**：買賣雙方約定運輸、報關、風險與部分費用由誰負擔的條件，會影響新增關稅最終由誰承受。
- **Annex（附件）**：正式公告附帶的清單，用來逐項列出適用品目、豁免或條件；它不是另一套獨立關稅。
- **原產地（country of origin）**：海關依實質轉型等規則認定商品來自哪個經濟體，不一定等於供應商總部、出貨港或最後組裝地。
- **Importer of record**：向美國海關申報、先負責分類、估價與繳納進口稅費的法律主體；它不必然是最後承擔成本的人。
- **關稅歸宿／轉嫁（incidence／pass-through）**：關稅由誰先繳，與最後由供應商、進口商、品牌、客戶或需求量吸收，是兩個不同問題。
- **Section 232**：美國以國家安全為由採取進口措施的另一套法律工具；同一商品若受 Section 232 管理，必須按 notice 的排除規則另外判讀。
- **EAR（Export Administration Regulations）**：美國商務部出口管理規則，管理受其管轄項目的出口、再出口與境內轉移；它不是進口關稅表。
- **ECCN**：美國 Commerce Control List 上用來做出口管制分類的五碼英數代號；BIS 明確說它與 HTS code 不同、彼此無關。
- **EAR99**：受 EAR 管轄、但未被 Commerce Control List 的特定 ECCN 收錄的項目；多數情境不需許可，不代表所有目的地、使用者與用途都可直接交易。
- **出口／再出口／境內轉移**：把受管制項目送出美國、由一個境外地點再送往別處，或在同一外國境內改交另一方的不同交易動作；適用判斷不能只看第一次出貨。
- **Entity List**：BIS 管理的出口管制名單；命中後可能新增許可要求並限制許可例外，不等於命中 OFAC 的 SDN List。
- **最終使用者／最終用途（end user／end use）**：最後由誰使用，以及拿去做什麼；即使項目分類或目的地本來不要求許可，特定使用者或用途仍可能改變結果。
- **OFAC**：美國財政部海外資產控制辦公室，執行制裁方案與相關交易限制；它和 BIS 的出口管制不是同一機關或同一套清單。
- **SDN List**：OFAC 的特別指定國民與被封鎖者名單；美國人通常不得與名單對象交易，並須依規則封鎖其受管財產。
- **制裁授權（general／specific license）**：OFAC 對原本可能受禁交易提供的一般或個別授權；它不是 BIS 出口許可，也不是客戶產品認證。
- **合格評定（conformity assessment）**：證明產品、流程或系統符合指定要求的活動，可包含供應商聲明、抽樣、測試、檢查、認證與認可。
- **第一方／第二方／第三方評定**：分別由供應商、買方／使用者或獨立機構執行的合格評定；「有測試」不必然等於已有獨立第三方證書或客戶簽收。
- **FAQ（常見問題）**：主管機關用問答澄清制度邊界的官方頁面；能支持頁面明載的通用解釋，不會自動替個案完成法律判定。

### 三句話抓重點

- USTR 已公布對台灣商品的最終行動，但 10% 是未豁免商品與 MFN 合計的框架，不是所有台灣科技品一律加徵。
- 電腦、伺服器相關品、半導體設備、資料傳輸設備與晶片等多類 HTS 已列入一般豁免，必須逐 code 判讀。
- 在取得公司實際報關分類、原產地、美國直出占比與 Incoterms 前，不能估算任何公司的毛利衝擊。

### 為什麼重要

政策新聞最容易把國家層級稅率誤寫成公司層級損益。真正的傳導要依序確認商品 code、豁免、
原產地、出貨路徑與合約承擔方；少一層都可能把本來豁免的伺服器或晶片，和未必豁免的裸
PCB、電源、散熱或被動元件混為一談。

### 接下來怎麼追

- 追 USTR／Federal Register 是否修改 Annex、豁免、在途規則或生效條件。
- 追公司一手文件或可追溯報關資料是否揭露實際 HTS、原產地、美國直出占比與 Incoterms。
- 優先核對裸 PCB、電源、散熱與被動元件，不用產品俗稱猜測報關分類。

### 想一想

- 同一台伺服器裡的整機、零件與材料，為什麼可能適用不同關稅結果？
- 即使某項產品未豁免，新增稅負一定由台灣供應商吸收嗎？
- 缺少公司報關 code 時，直接用美國營收占比估毛利衝擊會漏掉哪些變數？

## 為何值得進佇列

USTR 7 月 23 日公布最終行動；對未豁免的台灣商品，Section 301 稅與 MFN 稅合計以
10% 為框架，並自美東 7 月 24 日 00:01 起生效。附件初查同時顯示，電腦／伺服器、
其零件、半導體設備、網通傳輸設備與晶片等多個核心科技類別已列入一般豁免；因此這是
需要按 HTS code 分流的成本／需求風險，不是「所有台灣科技品一律加 10%」。在確認
原產地、實際報關分類與各公司的美國出貨／Incoterms 前，不能寫成任何一家公司的
毛利衝擊。

## 先分流：四種「受限制」不是同一件事

同一批 AI 伺服器、晶片或零件可能同時出現在進口、再出口、交易對手審查與客戶驗收流程，
但四種檢查的判斷單位不同。本文不是要替產品作法律或合格判定，而是先防止研究者拿其中
一張通行證，替另外三張背書。

| 本文四種檢查 | 判斷對象 | 最少要固定哪些欄位 | 可能得到的結果 | 通過後仍不知道什麼 |
|---|---|---|---|---|
| 進口關稅／Section 301 | 一筆進入美國的商品 entry | 商品形態、HTS、原產地、豁免、估價、進口主體與日期 | 適用稅率、豁免或其他 entry 條件 | 之後能否再出口、交易對手是否受制裁、產品是否通過客戶測試 |
| EAR 出口管制 | 受 EAR 管轄的商品、軟體、技術或特定活動 | 是否受 EAR 管轄、ECCN／EAR99、管制理由、目的地、交易各方、最終用途、許可與例外 | 不需許可、可用例外、需要許可或不得依預定方式進行 | 進口時繳多少關稅、OFAC 是否允許交易、客戶是否接受產品 |
| OFAC 制裁 | 人、實體、所有權、財產、地區、活動與交易 | 適用方案、名單／所有權、司法連結、交易活動、一般／個別授權 | 封鎖、拒絕／不進行，或在授權範圍內處理 | ECCN 與 EAR 許可結果、HTS 稅率、產品性能與可靠度 |
| 技術合格評定／客戶資格 | 指定產品、版本、流程或系統 | 要求、樣品、測試條件、執行者、原始結果、pass criteria、變更控制與簽核 | 通過、失敗、條件式接受或改版重驗 | 跨境交易是否合法、是否免稅、交易對手是否可收付款 |

四列可以同時成立，也可能由不同團隊在不同時間處理。它們不是固定先後順序：例如產品可以先完成
實驗室測試，仍在等待出口許可；也可以依法進口，卻尚未通過買方 qualification。

### HTS 與 ECCN 都是代碼，卻回答不同問題

HTS 服務進口商品分類與稅率；ECCN 服務出口管制分類。BIS 的現行分類頁直接寫明兩者
「不同且完全無關」，並要求先確認項目是否受 EAR 管轄，再依 ECCN、管制理由與目的地判斷
許可需求。即使項目是 EAR99，特定目的地、最終使用者或用途仍可能觸發許可，因此也不能把
「沒有特定 ECCN」改寫成「沒有出口限制」。

### 同樣出現在「清單」，BIS 與 OFAC 的後果仍不同

BIS 的 Entity List、Denied Persons List 等服務出口／再出口／境內轉移管制；OFAC 的 SDN
與其他制裁名單服務其各自的制裁方案。OFAC 官方 FAQ 明示兩邊的法律目標與要求不同，不能
合成一張清單。研究工作底稿至少要分開保存命中哪張名單、哪個法規、涉及哪一方、要求許可、
封鎖、拒絕還是可以依授權進行，不能只寫「被美國列管」。

### 技術合格也不等於只有一張第三方證書

NIST 把合格評定拆成供應商聲明、抽樣與測試、檢查、認證、管理系統評估與認可，執行者也可能是
供應商、買方、獨立第三方或政府。對 AI 硬體而言，元件實驗、平台 qualification、客戶簽收與
量產變更重驗可能是不同證據物件；其中任一張 pass report 都不會替 HTS、EAR 或 OFAC 作答。

### 同一產品要留下四欄，而不是一個「合規」標籤

研究中心對具名產品至少分開記錄：`entry／HTS／origin`、`EAR scope／ECCN／destination／
parties／end use`、`OFAC program／party／ownership／authorization`、`requirement／test／
pass／change control`。四欄沒有同一產品、版本、交易、日期與責任人時，只能說哪一欄已有
資料；不能把「合法進口」「不需出口許可」「未命中制裁」或「客戶測試通過」互相替代，更不能
直接寫成公司出貨、收入或毛利已受影響。

## 先用七關把國家稅率拆到公司財務

國家名稱和 headline rate 只是第一關。要把政策落到公司，七關必須依序保留；前一關的
答案不能替後一關作答。

| 關卡 | 要回答的問題 | 本文目前能證明什麼 | 還缺什麼 |
|---|---|---|---|
| 1. 政策行動與範圍 | 哪個法律行動、經濟體、稅率公式、生效與在途規則適用？ | 正式刊登 notice 支持台灣的 10% 合計稅率公式與生效框架 | 後續修正、corrigendum 或執行指引 |
| 2. HTS 商品分類 | 實際進口品在 entry 上使用哪個 HTS code？ | Annex 可按 code 查規則 | 公司料號、組態與報關 code 的可追溯對照 |
| 3. Annex 豁免 | 該 code 是否落入一般豁免、Section 232 排除或其他條件？ | 多類電腦、設備、傳輸與半導體 code 已列在一般豁免 | 每個具名產品的 code 與豁免逐項核對 |
| 4. 海關原產地 | 商品依法被認定來自哪裡？ | 政策以進口商品與適用經濟體執行 | 實質轉型、製程、工廠與 ruling／申報依據 |
| 5. 出貨與交易責任 | 誰是 importer of record，Incoterms 與合約如何分配先繳責任？ | Notice 規定 entry 與在途條件 | 直出占比、進口主體、報價幣別、Incoterms 與價格調整條款 |
| 6. 需求與成本轉嫁 | 稅後價格由誰吸收，數量、替代與議價如何反應？ | 尚無公司級證據 | 客戶協商、替代路徑、價格／量變化與實際 pass-through |
| 7. 公司財務歸因 | 多少收入、成本、毛利與現金流可歸因於這項政策？ | 尚無可重建的公司分母 | 同一產品、期間、數量、價格、成本與公司總額的橋接 |

這七關刻意把「法律上是否課到」和「經濟上誰受影響」拆開。第 1–3 關多半是規則與商品
問題，第 4–5 關是海關與交易問題，第 6–7 關才開始成為需求與財務問題。

### 同一商品有三個名字

- **銷售名稱／SKU**回答客戶買了什麼，通常服務產品管理與報價。
- **海關 HTS code**回答 entry 如何分類，會因功能、材質、組態或完成度而不同。
- **會計 segment**回答公司把收入與損益放在哪個揭露分母，通常比 SKU 粗很多。

因此，「AI 伺服器營收」不能直接替代伺服器內每個進口零件的 HTS；某個 HTS 被豁免，
也不能直接推出整個會計 segment 都不受影響。

### 關稅由誰先付，和誰最後吸收，是兩個問題

Importer of record 先向海關負責，不代表它一定獨自承擔經濟成本。之後可能透過調價、
供應商折讓、重新議價、改變原產與出貨路徑、轉向替代品，或讓需求量下降而分散。沒有
合約條款與實際價格／數量資料時，只能列出可能的傳導路徑，不能指定最後輸家。

### 新手最常混淆的六件事

1. **「台灣 10%」不等於每項台灣商品再加 10 個百分點。** 本案要把既有 MFN 與 Section 301 公式合併判讀。
2. **商品來自台灣，不等於供應商總部在台灣。** 原產地是商品規則，不是公司國籍標籤。
3. **整機豁免，不等於所有單獨進口零件也豁免。** Entry 的商品形態與 HTS 才是判斷單位。
4. **美國營收占比，不等於美國進口曝險。** 還要知道出貨地、原產地、進口主體與交易條件。
5. **先繳關稅，不等於最後吸收關稅。** 稅負可能經價格、數量與供應鏈重新配置轉移。
6. **成本方向，不等於公司損益金額。** 沒有產品分母與公司總額橋接，不能寫毛利率衝擊。

### 在研究中心裡接著怎麼學

讀完本篇，可接著讀「半導體 PFAS 七關曝險鏈」：兩篇都從法規文字出發，但 Section 301
主要沿商品分類、原產地與交易責任傳導；PFAS 則沿物質身分、製程用途、法域義務與變更
資格傳導。把兩條路放在一起，能看見「政策已發布」和「公司財務已受影響」之間為何總有
多個不可省略的交接點。
